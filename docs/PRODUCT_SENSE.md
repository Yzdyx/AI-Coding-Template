# 产品决策

本文档定义产品决策的方式与风险分级标准。它回答「一个需求值不值得做、风险有多大、由谁决定」。规格正文见 [`product-specs/index.md`](product-specs/index.md)，设计约束见 [`DESIGN.md`](DESIGN.md)。

## 1. 决策原则

| 编号 | 原则 | 含义 |
| --- | --- | --- |
| D1 | 先定义问题，再定义方案 | 问题用事实描述，方案是问题的候选答案 |
| D2 | 明确非目标 | 每次决策都写明不做什么，防止范围蔓延 |
| D3 | 风险决定流程 | 风险越高，需要的评审与审批越重，见第 2 节 |
| D4 | 可度量 | 每个决策都有成功指标与观察窗口 |
| D5 | 可回滚 | 上线前确定回滚条件与回滚方式 |
| D6 | 边界优先 | 能用结构或策略表达的约束，不靠提示词或人工提醒 |

## 2. 风险分级

风险分级决定决策流程与所需审批。风险等级同时写入执行计划元数据的 `risk.level`，见 [`PLANS.md`](PLANS.md)。

| 等级 | 判定标准 | 决策与审批 | 示例 |
| --- | --- | --- | --- |
| `low` | 只读、无外部副作用、可随时回滚 | 团队内决定，普通评审 | 文档改动、前端文案调整、只读查询优化 |
| `medium` | 影响单个 Agent 或模块，无生产写入 | 模块所有者评审 | 检索超时与降级、评测数据集扩充 |
| `high` | 跨模块、写入生产、影响多个 Agent | 模块所有者 + 架构或安全会签，灰度发布 | 工具网关全量上线、权限模型变更 |
| `critical` | 不可逆生产写入、影响合规或数据安全 | 上述全部 + 安全团队会签 + 人工审批节点 | 生产数据迁移、权限策略变更、密钥轮换 |

判定规则：

1. 只要命中「生产写入」，风险至少为 `high`，且 `risk.production_write` 必须为 `true`。
2. 只要命中「不可逆」，风险为 `critical`，且必须有阻塞式人工审批节点，见 [`SECURITY.md`](SECURITY.md)。
3. 跨模块改动即使无写入，风险至少为 `medium`。
4. 风险等级取所有判定标准中的最高值，不取平均。

## 3. 决策流程

| 步骤 | 动作 | 产出 |
| --- | --- | --- |
| 1 | 定义问题：谁在什么场景下遇到什么问题 | 问题陈述 |
| 2 | 定义目标与非目标 | 目标列表、非目标列表 |
| 3 | 风险分级 | `risk.level`、`risk.production_write` |
| 4 | 定义验收标准与成功指标 | 可判定的验收条目、指标与目标值 |
| 5 | 确定发布与回滚方式 | 灰度策略、回滚条件 |
| 6 | 转化为执行计划 | [`PLANS.md`](PLANS.md) 描述的计划文档 |
| 7 | 上线后回顾 | 指标是否达成、是否触发回滚 |

规格冻结后不再改动验收标准。确需变更时，记录变更原因与影响，并按新的风险等级重新走流程。

## 4. 优先级判定

优先级由影响与代价共同决定，不用单一维度排序。

| 因素 | 提高优先级 | 降低优先级 |
| --- | --- | --- |
| 影响用户数 | 影响多 | 影响个别用户 |
| 风险敞口 | 消除安全或授权风险 | 仅体验优化 |
| 可靠性 | 影响错误预算或 SLO | 无可靠性影响 |
| 依赖关系 | 解锁其他任务 | 被其他任务阻塞 |
| 代价 | 小改动大收益 | 大改动小收益 |

安全与可靠性问题优先于新功能。涉及错误预算的事项见 [`RELIABILITY.md`](RELIABILITY.md)，涉及质量下滑的事项见 [`QUALITY_SCORE.md`](QUALITY_SCORE.md)。

## 5. 反模式

| 反模式 | 后果 | 正确做法 |
| --- | --- | --- |
| 用方案代替问题陈述 | 无法判断方案是否解决了真实问题 | 先写问题，再写方案 |
| 不写非目标 | 范围持续蔓延，交付延期 | 每次决策明确排除项 |
| 用提示词兜安全 | 概率性约束不可靠 | 用策略引擎与审批节点，见 [`SECURITY.md`](SECURITY.md) |
| 低估生产写入风险 | 事故不可逆 | 生产写入至少 `high` 且需审批 |
| 上线前不定回滚条件 | 出问题无法快速止损 | 上线前确定回滚触发条件 |
