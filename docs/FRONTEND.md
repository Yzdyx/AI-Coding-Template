# 前端约定

本文档定义前端（`apps/admin-console/`）的 UI 约定、设计 token 来源、可访问性与状态管理规则。前端属于 `UI` 层，只依赖 `Runtime` 与 `Types`，见 [`architecture/dependency-rules.md`](architecture/dependency-rules.md)。总体设计原则见 [`DESIGN.md`](DESIGN.md)。

## 1. 适用范围

| 项目 | 说明 |
| --- | --- |
| 适用 | `apps/admin-console/` 下的组件、样式、表单、路由、状态 |
| 不适用 | 业务 Agent 的提示词与工具实现；后端接口定义 |
| 依赖边界 | `UI` 只允许依赖 `Types`、`Runtime`、`UI`，禁止直接 import `Service`、`Repo`、`Config` |
| 评审 | 由 `@app-team` 评审，信息架构改动需产品会签 |

## 2. 分层与数据获取

1. 界面通过 `Runtime` 暴露的接口获取数据与发送命令，不直接访问数据层。绕过 `Runtime` 等于绕过授权与审计装配。
2. 展示用的形状来自 `Types` 层，禁止在组件内重新定义接口形状。
3. 权限判断由 `Runtime` 完成，界面只根据返回结果展示，不在前端实现授权逻辑。

| 做法 | 判定 | 理由 |
| --- | --- | --- |
| 组件调用 `Runtime` 暴露的查询接口 | 允许 | 经过授权与审计装配 |
| 组件直接 import `Service` | 禁止 | 越层，绕过 `Runtime` |
| 组件直接读取配置 | 禁止 | 配置由 `Runtime` 注入 |
| 组件持有密钥或令牌 | 禁止 | 见 [`SECURITY.md`](SECURITY.md) |

## 3. 设计 token

所有颜色、间距、字号、圆角、阴影与动效时长必须来自设计 token，禁止在组件里写死数值。

设计 token 的唯一事实来源是设计系统参考文件，路径为 [`references/design-system-reference-llms.txt`](references/design-system-reference-llms.txt)。新增或修改 token 时，先更新该参考文件，再在样式层引用；不得在组件中引入参考文件之外的一次性数值。

| 类别 | 使用规则 |
| --- | --- |
| 颜色 | 只使用语义 token（如 `color-text-primary`），禁止使用原始色值 |
| 间距 | 只使用刻度值，保持节奏一致 |
| 字号与行高 | 只使用预设层级，禁止临时设定 |
| 圆角与阴影 | 只使用预设层级，保持视觉统一 |
| 动效时长 | 使用预设时长，尊重用户的减少动效偏好 |

## 4. 组件约定

1. 组件按职责分层：基础组件（无业务语义）、组合组件（有布局语义）、页面组件（有业务语义）。
2. 基础组件不感知业务数据；业务数据通过属性传入，不在基础组件内发起请求。
3. 每个组件只做一件事。出现「同时负责布局、数据获取与校验」的组件时，拆分。
4. 组件属性使用 `Types` 层声明的类型，禁止使用 `any`。
5. 组件命名使用描述性名称，禁止 `Container`、`Wrapper` 之类无信息量的名字。

## 5. 状态管理

| 状态类型 | 存放位置 | 生命周期 | 说明 |
| --- | --- | --- | --- |
| 服务端数据 | 查询缓存层 | 由失效策略控制 | 只缓存 `Runtime` 返回的数据，不复制业务规则 |
| 界面状态 | 组件本地状态 | 组件挂载周期 | 展开、选中、临时输入等 |
| 跨页面共享状态 | 全局状态容器 | 应用周期 | 仅存放真正跨页面的少量状态 |
| 表单状态 | 表单控制器 | 表单生命周期 | 校验规则与提交状态就近管理 |

规则：

1. 服务端数据与界面状态分开存放，禁止把服务端数据复制进全局状态容器。
2. 全局状态只放跨页面共享的内容，避免把局部状态提升为全局。
3. 状态更新保持单向数据流，禁止在展示组件内直接改写全局状态。

## 6. 可访问性

1. 所有交互元素可通过键盘操作，焦点顺序与视觉顺序一致。
2. 每个交互控件有可读的名称，图片有替代文本。
3. 文本与背景的对比度满足 WCAG AA。
4. 状态变化通过语义化元素或 `aria-live` 通告，不只靠颜色区分。
5. 尊重用户的减少动效偏好，动效不承载唯一信息。
6. 表单错误信息与对应字段关联，错误可被屏幕阅读器读取。

可访问性缺陷按 [`QUALITY_SCORE.md`](QUALITY_SCORE.md) 的评分规则计入前端领域质量。

## 7. 错误与加载状态

1. 每个数据获取点都有加载态、空态与错误态三种呈现，禁止只处理成功态。
2. 错误信息可分类：权限错误、超时、上游失败，分别给出可恢复的下一步操作。
3. 失败不重置用户已输入的内容。
4. 长时间操作有进度反馈，且可取消。

## 8. 前端评审清单

| 编号 | 检查项 |
| --- | --- |
| F1 | 未越层依赖，数据经 `Runtime` 获取 |
| F2 | 所有样式值来自设计 token，无写死数值 |
| F3 | 组件职责单一，属性类型来自 `Types` |
| F4 | 服务端数据与界面状态分离 |
| F5 | 键盘可达、名称可读、对比度达标 |
| F6 | 加载、空、错误三态齐全且可恢复 |
| F7 | 改动与 [`DESIGN.md`](DESIGN.md) 的设计原则一致 |
