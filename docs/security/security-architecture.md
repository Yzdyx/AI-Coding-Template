# 安全架构

本文档描述身份、授权、密钥、审计的架构细节。信任边界与威胁清单见 [`threat-model.md`](threat-model.md)，工程要求见 [`../SECURITY.md`](../SECURITY.md)。

## 1. 信任边界

| 边界 | 内侧 | 外侧 | 跨越方式 |
| --- | --- | --- | --- |
| 用户到平台 | 平台运行时 | 用户与浏览器 | 认证后的 HTTPS 请求 |
| 平台到模型提供方 | 平台运行时 | 外部模型服务 | 经网关的出站调用，携带短期凭据 |
| 平台到外部连接器 | 平台运行时 | 第三方系统 | `ConnectorProvider`，逐工具授权 |
| Agent 到工具 | Agent 运行时 | 工具实现 | 工具网关，带策略判定 |
| 租户之间 | 单个租户的数据 | 其他租户 | 租户标识强制注入，禁止由调用方提供 |

## 2. 身份

| 主体 | 标识 | 凭据 | 生命周期 |
| --- | --- | --- | --- |
| 操作员 | 企业身份提供方主体 | OIDC 令牌 | 短期，自动续期 |
| 服务 | 服务账户 | 工作负载身份 | 随实例 |
| Agent 运行 | 运行标识（`run_id`） | 由运行时签发 | 单次运行 |
| 外部系统 | 连接器注册标识 | 由密钥服务托管 | 轮换 |

身份解析由 `IdentityProvider` 承担，实现位于 [`../../packages/tool-adapters/src/identity.ts`](../../packages/tool-adapters/src/identity.ts)。任何层都不得自行解析令牌。

## 3. 授权

1. 所有工具调用先经策略判定。判定输入为：主体、工具、参数摘要、租户、会话上下文。
2. 策略引擎必须**失败即拒**（fail closed）。判定不可用时拒绝调用，不降级为放行。
3. 高风险工具需要人工审批节点。审批记录包含审批人、时间与理由。
4. 授权逻辑集中在 [`../../packages/policy-engine/`](../../packages/policy-engine/) 与 [`../../infra/policies/`](../../infra/policies/)。禁止在 `Service` 或 `UI` 内联权限判断。

## 4. 密钥与凭据

| 规则 | 说明 |
| --- | --- |
| 不落仓库 | 任何密钥、令牌、私钥都不进入版本控制，也不进入测试夹具 |
| 环境变量注入 | 配置通过环境变量引用，配置文件只写变量名 |
| 最小权限 | 每个连接器只授予其任务所需的权限范围 |
| 可轮换 | 每个凭据有轮换周期与轮换步骤 |
| 可撤销 | 泄露时的撤销路径必须已知且演练过 |

## 5. 数据保护

1. 租户隔离在数据访问层强制，不依赖调用方传入的租户标识。
2. 日志、trace 与评测数据中的提示词、模型输出与检索内容按敏感数据处理：脱敏、访问控制、保留期限。
3. 导出数据需要审批，导出行为写入审计。
4. 删除请求必须覆盖主存储、索引与备份策略。

## 6. 审计

审计记录不可篡改，至少包含：

| 字段 | 说明 |
| --- | --- |
| `trace_id` | 端到端链路标识 |
| `run_id` | 单次 Agent 运行标识 |
| `subject` | 发起主体 |
| `tool` | 被调用工具 |
| `decision` | 允许、拒绝、待审批 |
| `approver` | 审批人（存在审批时） |
| `idempotency_key` | 副作用幂等键 |

审计记录与 [`../generated/db-schema.md`](../generated/db-schema.md) 中的表结构保持一致。
