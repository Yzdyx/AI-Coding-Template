# 新用户引导

- 规格编号：SPEC-0001
- 状态：Active
- 负责人：`@product-team`
- 目标版本：2026.1
- 相关文档：[`index.md`](index.md)、[`../PRODUCT_SENSE.md`](../PRODUCT_SENSE.md)、[`../FRONTEND.md`](../FRONTEND.md)、[`../QUALITY_SCORE.md`](../QUALITY_SCORE.md)、[`../RELIABILITY.md`](../RELIABILITY.md)、[`../SECURITY.md`](../SECURITY.md)、[`../exec-plans/active/AGENT-1042-improve-retrieval-timeout.md`](../exec-plans/active/AGENT-1042-improve-retrieval-timeout.md)

## 1. 问题

新用户第一次进入管理控制台（`apps/admin-console/`）时，面对的是一个空的 Agent 列表、一组需要理解的概念（Agent、工具、策略、评测）和一条不清晰的接入路径。实际反馈集中在三点：

1. 不知道该从哪里开始：仓库里同时有编码 Agent 工程体系与运行时 Agent 应用体系，新用户容易混淆二者的职责。
2. 缺少可运行的起点：用户希望先看到一个能跑起来的 Agent，而不是先读文档。
3. 权限与安全边界不透明：用户不清楚哪些操作会触发人工审批，担心误操作生产环境。

结果是新用户在上手阶段大量求助，首次成功运行一个 Agent 的时间过长，且经常在权限问题上卡住。

## 2. 目标

1. 新用户在一次会话内完成从登录到运行第一个示例 Agent 的完整流程。
2. 引导过程显式展示权限边界：哪些动作是只读的，哪些会触发人工审批，哪些在生产环境默认关闭。
3. 引导结果可度量：能观察到完成率、卡点位置与首次成功时间。
4. 引导内容与既有文档一致，不复制规则，只引用入口。

## 3. 非目标

1. 不构建独立的引导服务，引导逻辑复用现有 `apps/admin-console/` 与 `apps/agent-api/`。
2. 不实现完整的租户自助注册，本期只覆盖邀请制用户的首次上手。
3. 不改动权限模型与审批关卡，引导只做展示，不新增授权路径。
4. 不覆盖业务 Agent 的内部实现教学，只覆盖平台使用路径。

## 4. 用户流程

主路径（Happy path）：

| 步骤 | 用户动作 | 系统反馈 | 失败分支 |
| --- | --- | --- | --- |
| 1 | 通过邀请链接登录 | 展示欢迎页与三步引导清单 | 邀请失效：提示联系管理员 |
| 2 | 选择示例 Agent | 展示该 Agent 的用途、所需工具、权限范围 | 无可用示例：回退到空状态说明 |
| 3 | 查看权限提示 | 明确标出只读步骤与需审批步骤 | 用户无权运行：展示所需角色 |
| 4 | 运行示例 Agent（只读） | 返回运行结果与 trace 链接 | 运行失败：展示错误分类与重试入口 |
| 5 | 查看运行轨迹 | 展示模型、工具、审批节点调用序列 | trace 不可用：提示稍后重试 |
| 6 | 完成引导 | 展示下一步入口（创建自己的 Agent） | 用户中途离开：进度保留，下次续接 |

关键决策点：

1. 步骤 3 是安全边界展示点。凡是会触发人工审批的动作，必须在此处提前告知，而不是在执行时才提示。
2. 步骤 4 默认只读，不写入任何外部系统，符合 [`../SECURITY.md`](../SECURITY.md) 的默认安全原则。
3. 步骤 6 不强制用户继续，允许保存进度后离开。

失败分支必须可恢复。任何一步失败都不应把用户重置到起点，进度以用户维度持久化。

## 5. 验收标准

| 编号 | 验收标准 | 验证方式 |
| --- | --- | --- |
| AC-1 | 邀请制用户登录后能看到三步引导清单 | 前端集成测试 |
| AC-2 | 示例 Agent 可被选中并展示其用途、工具与权限范围 | 前端集成测试 |
| AC-3 | 只读步骤不写入任何外部系统，审批步骤提前标注 | 安全评测与人工核对 |
| AC-4 | 运行示例 Agent 返回结果并给出 trace 链接 | 端到端测试 |
| AC-5 | 中途离开后重新进入能续接进度 | 前端集成测试 |
| AC-6 | 引导页面不复制规则文本，只引用既有文档入口 | 文档链接检查 |
| AC-7 | 任一失败分支都有可恢复的下一步操作 | 端到端测试 |

验收标准冻结后不再改动。确需变更时按 [`../PRODUCT_SENSE.md`](../PRODUCT_SENSE.md) 记录变更原因与影响。

## 6. 成功指标

| 指标 | 定义 | 目标值 | 观察窗口 |
| --- | --- | --- | --- |
| 引导完成率 | 完成步骤 6 的用户 / 进入引导的用户 | ≥ 70% | 上线后 4 周 |
| 首次成功运行时间 | 从登录到步骤 4 成功的时长中位数 | ≤ 10 分钟 | 上线后 4 周 |
| 权限相关求助率 | 因权限问题提交的求助 / 完成引导的用户 | 下降 50% | 上线后 8 周 |
| 步骤流失点 | 各步骤放弃率 | 无单步放弃率 > 20% | 上线后 4 周 |

指标按周采集，进入 [`../QUALITY_SCORE.md`](../QUALITY_SCORE.md) 的观察范围。指标恶化时触发回滚评估。

## 7. 发布方式

1. 灰度：先对内部团队开启，观察一周，确认无权限相关问题后再扩大到邀请制用户。
2. 开关：引导入口由特性开关控制，默认关闭，按租户开启。
3. 回滚条件：出现任一安全边界展示错误，或完成率低于 40%，立即关闭开关并回滚。
4. 监控：完成率、步骤流失点、错误分类进入运行看板，与 [`../RELIABILITY.md`](../RELIABILITY.md) 的错误预算一起观察。
5. 关联计划：本规格的实现任务记录在 [`../exec-plans/active/AGENT-1042-improve-retrieval-timeout.md`](../exec-plans/active/AGENT-1042-improve-retrieval-timeout.md) 所属的任务序列中，验收证据在计划归档时一并提交。
